# GlassLingo 0.17.0 使用说明

## 启动

退出托盘中仍在运行的旧版本，再运行本发布目录的 `GlassLingo.exe`。请保留相邻 DLL、`inference` 模型目录及其它依赖文件。程序自包含 .NET 运行时。

新版发现旧进程时会显示实际版本，避免打开新版却静默唤起旧版。

关闭控制面板会收回托盘，不会退出软件。双击托盘图标或按控制面板快捷键可以重新打开；完全退出请用托盘菜单。

## 输入翻译小窗

默认使用 400×276 DIP 的简洁版：保留输入框、译文框、目标语言，以及译文区的复制按钮。输入或粘贴后停顿约 420 ms 自动翻译，**Enter 换行，无需按键提交**；切换语言也会自动重译。完整版使用同样的自动输入方式，额外提供停止和重试按钮。模式切换保留草稿与译文，下次呼出记住选择。

按 **Ctrl+Shift+I**、主面板或托盘“输入翻译”呼出。目标语言单独记住；源语言由翻译模型自动判断，不依赖 OCR。Ctrl+Shift+C 或复制按钮复制译文，Esc 关闭。快捷键可以在设置中重新录入。

输入停顿后会自动发送到已配置的翻译服务，最多 20000 字符，不保存历史。输入法组字期间等待提交，不逐字发请求。打开小窗不停止区域监测，也不加载 Paddle。编辑输入或更改目标会取消旧请求；重复呼出激活同一窗口。缺少 API 时可进入设置，保留当前草稿。

## 多区域与文字跟随

重复按 Ctrl+Shift+R（或面板“添加区域”）可以追加区域，最多同时 8 个。在主面板“区域”入口管理，各区可独立暂停、隐藏译文、移除；主面板的暂停、隐藏和停止作用于全部活动区域。区域管理嵌在主窗口中。

“设置 → 外观与显示 → 译文跟随原文”默认开启。原位译文根据 OCR 识别到的原文身份更新坐标，滚动、换位后复用已有译文；新对白等待翻译时保留上一条可读译文，避免突然空白；匹配到的已译行继续跟随坐标。框选/全屏的一次翻译只跟随已经翻译的文字，想自动翻译新对白请使用区域持续翻译。普通浮窗仍可保留，并能切换成原位覆盖。

源窗口移动时使用轻量窗口坐标更新；窗口内部滚动和文字移动受 OCR 采样间隔影响，并非逐帧追踪。窗口最小化、离开屏幕或原文消失时隐藏对应覆盖；恢复后立即按已有坐标重现，后续 OCR 再校准。暂时的 OCR 或截图错误不会结束监测；翻译服务异常会自动退避重试，最长间隔 30 秒，新文字无需等待旧重试结束。API OCR 目前没有文字坐标，需手动选择侧栏或浮窗阅读，不能逐字框跟随。

所有屏幕区域共用一个 OCR 引擎；Paddle 共用一个模型进程。识别串行执行，屏幕翻译请求最多并行 2 个。区域越多、越大，更新越慢；游戏建议只选字幕附近的小区域。关闭后释放模型资源。

## 屏幕翻译模式

默认显示：框选翻译 → 弹窗，全屏翻译 → 侧栏，区域持续翻译 → 原位覆盖。升级到 0.10.0 首次恢复这组默认，之后手动修改的偏好继续保存。主界面先排列翻译入口，每个入口标出快捷键和当前显示方式，显示设置与引擎信息放在下方。

翻译结果只显示正文，自动移除模型额外添加的“原文／译文”等格式标签；技术文本的括号释义仍保留。逐字出现的对白可在持续增长约 1.2 秒后更新，不必无限等待完全相同的识别结果。

区域默认每秒检查约 2 次，OCR 最短间隔 500 ms，确认真实文字变化后更新。流式输出将收到的一批文字在约 80 ms 内平滑显示，当前生成行无需等到换行结束；无待显示内容时不运行动画计时器。网络首字、OCR 耗时及多区域排队仍会影响实际延迟。

- **框选翻译**：选择一块文字，识别并翻译一次。
- **全屏翻译**：翻译鼠标所在显示器的一张截图，不会持续扫描整个屏幕。全屏原位覆盖在完整译文可按行对应时显示；布局不能对应时隐藏该次覆盖，按需要手动切换侧栏。
- **区域持续翻译**：框定游戏对话或字幕区域。默认每 500 ms 检查画面，变化后按 OCR 最短间隔识别；先确认文字稳定变化，再更新译文；相同文字复用结果。关闭画面监测需按“停止”，单独隐藏译文不会停止识别和请求。

区域可跟随选中的窗口移动、缩放；窗口最小化时等待恢复。请保持选区在同一个显示器内；混合 DPI、多显示器切换后建议重选。先将鼠标移到目标屏幕再触发选择。

## 图形误识别过滤

“设置 → 文字识别 → 过滤图形与可疑识别”默认开启。跳过纯符号、异常细线/过宽文字框、重复笔画和低置信度 Paddle 结果，过滤后没有文字就不发送翻译请求；不额外加载图像模型。数字、快捷键字母、正常中日韩文字、路径和代码名继续保留。若真实短字被过滤，可关闭此项。

0.12.0 放宽了对真实短字的置信度要求，仍过滤明显低分结果。局部小图在漏识别或小字不清时可做一次 2 倍放大重试，重试至少间隔 2 秒并限制尺寸，不增加翻译请求。

Windows OCR 不提供识别置信度；图形若被模型认成正常汉字仍可能漏过，不能保证所有画面零误识别。选区尽量贴近字幕、避开图标，有助于减少误判。

## 三种显示方式

- **翻译浮窗**：可复制译文，展开原文和诊断；在窗口内按 Esc 关闭。
- **原位覆盖**：只显示译文，没有矩形边框或装饰圆角，鼠标点击穿透，不获取游戏焦点。译文逐行贴近原文字框，字号按原文字高和屏幕 DPI 自适应；设置中的字号是上限。同一位置的小幅识别抖动和流式增量不会改变字号。多行 OCR 通过内部行编号对应译文与原文框，一次请求完成；编号不会显示。译文宽度固定在原文字框附近，密集行按行距适配字号。重复 Paddle 框会合并，重叠框不会同时绘制。无法完整容纳的长译文仍需切到浮窗或侧栏阅读。分散标签等无法可靠对应的布局仍隐藏覆盖，不自动弹出窗口；可手动切换侧栏查看完整内容。底色颜色及透明度可在外观与显示中调整。内容过多时请扩大区域或切到浮窗阅读完整内容。
- **侧栏**：将整段文字放在屏幕右侧，适合全屏内容多或 API OCR 没有文字坐标的情况。

主面板先选择“框选 / 全屏 / 区域监测”，再调整对应的显示方式；三种偏好分别保存。活动会话的显示方式可即时切换，不重复请求 API。

## 玻璃质感与透明度

默认使用不透明背景，保留较弱的左上、右下玻璃高光。

在“设置 → 外观与显示”单独勾选“启用透明背景”，再调主界面和翻译浮窗各自的透明度滑块；关闭后恢复不透明，保留上次滑块数值。0% 不透明、100% 透明，只影响底色，文字和按钮保持清晰。透明开启后能清楚看见下层画面，不施加背景模糊。普通翻译浮窗底部也有透明开关及底色调节。

游戏原位字幕只保留无边框文字衬底与轻量字影，不启用背景模糊或持续折射动画。可在外观与显示页调整字号上限和衬底。当前材质为清晰透明背景与低透明高光，不是苹果系统的物理折射渲染。

关闭效果、高对比度或材质不可用时使用实色回退。透明度极高时，明亮、复杂背景会影响阅读，可降低透明度。游戏中建议收起主面板，仅保留字幕。

升级时，旧版原位底色的全透明或 35% 不透明默认值会恢复为更清楚的深色底（18% 透明）。其它自定义数值保留；升级后可重新调为全透明。

在“设置 → 外观与显示 → 覆盖译文底色”勾选启用底色，选择石墨、黑、深蓝、暖白或输入自定义 #RRGGBB 颜色。拖动底色透明度滑块：0% 为完全不透明，100% 为完全透明；文字本身不变淡。下方即时预览效果，保存后用于原位译文。浅色底会自动搭配深色文字。关闭底色仅移除背景，保留译文。

## 界面语言与外观

“设置 → 外观与显示 → 界面语言”提供简体中文、繁体中文、English、日本語、한국어。切换立即预览，保存后下次启动沿用；取消或关闭未保存的设置会恢复先前界面语言。界面语言独立于源语言、翻译目标语言、模型和提示词内容。

语言包已内置，不需要联网或调用 API。设置、主面板、托盘菜单、浮窗及常用运行提示一起本地化。截图文字、译文和可编辑提示词作为内容保留原样；底层第三方服务的原始错误可能仍使用服务商的语言。

主面板和翻译浮窗使用接近 Windows 11 弧度的单个 8 DIP 透明圆角，所有图层沿同一轮廓裁剪，没有额外方形底板；最大化变为直角。清晰透明窗口不使用系统毛玻璃阴影。原位字幕仍无边框和装饰圆角。设置在主窗口内打开，不创建第二个设置窗口；左上角返回箭头或 Esc 取消草稿并返回翻译页，保存操作固定在底部。界面语言与玻璃浓度可预览。

滚轮使用可累计、可中断的 170 ms 平滑滚动；拖动滚动条或使用键盘会取消旧滚动动画。页面、标签和浮窗使用短过渡，遵循系统动画开关；不会让 Window 整体淡入导致玻璃失效。鼠标点击不会留下常驻白框，键盘导航仍显示焦点提示。

窗口完整绘制到四边，去掉白条，保留统一透明圆角。下拉菜单使用约 160 ms 展开、100 ms 收起过渡，箭头同步转动；选项即时生效，快速反复开关会从当前状态继续。系统关闭界面动画时直接开关。设置关闭时会清理尚在收起的菜单。

## 识别引擎

- **Windows OCR**：系统自带，依赖已安装的 OCR 语言包。未安装日语语言包时无法据此可靠识别日语。
- **PaddleOCR**：本机离线识别；在独立低优先级进程中按需加载模型。默认 2 个推理线程，可调 1/2/4。停止会话后释放工作进程；首次加载比后续识别慢。
- **视觉 API OCR**：需要支持图片输入的模型及独立的 API 地址、模型名和密钥。截图会上传到该服务商；持续模式的 OCR 请求至少间隔 2.5 秒。没有可靠坐标时原位覆盖保持隐藏，需要手动选择侧栏或浮窗。

翻译模型与 OCR 引擎独立选择。翻译 API 会接收识别文字；密钥存于 Windows 凭据管理器，配置只记录引用。

## 游戏低占用设置

建议从“每秒检查 2 次、OCR 最短间隔 750 ms、Paddle 2 线程”开始；如果游戏 CPU 已满，改为 1 线程和更长检查间隔。只选字幕/对话区，避免把整段动态游戏画面当监测区。

画面变化只触发有间隔的文字检查，不会直接重建字幕。空格、换行和大小写差异不重译；新对白需连续两次一致，普通检查后允许一次约 120 ms 的快速复核；长句中单字疑似误识别需三次。短暂漏识别不会清空字幕，持续空白约 1.5 秒以上才确认消失。数字变化正常确认，不会被近似比较吞掉。

快速复核不会无限连续运行，动态打字画面仍受普通间隔约束；视觉 API OCR 仍遵守至少 2.5 秒的请求间隔。翻译期间保留上一条译文，流式片段更新同一文字控件；过期回复不能覆盖新对白。动态背景仍可能触发 OCR，此修复不表示 OCR 完全停止。

Paddle 仅在开始框选时预热，让模型加载与拖动选区重叠；取消、停止仍释放进程，不在待机时常驻模型。冷启动加载本身仍需时间。普通浮窗/侧栏在识别阶段就显示等待状态，原位字幕仍只显示译文。已去掉稳定确认后额外 160 ms 的翻译等待。

流式译文收到一部分就显示；供应商不支持时可在设置关闭。全屏原位覆盖需要完整的行映射，因此可能等完整回复后再贴回；浮窗、侧栏和区域覆盖可提前显示文本。

窗口或无边框全屏优先。独占全屏、受保护画面、部分反作弊环境、HDR 与不同 GPU 路径仍需逐游戏验证。当前未做真实游戏 FPS 对照，不能将合成测试结果当成游戏帧率保证。

## 暂停、隐藏与停止

暂停停止新的截图/OCR/翻译，保留会话以便恢复；隐藏只隐藏结果，监测仍继续；停止取消会话、移除底板和译文，并释放 Paddle 模型进程。网络或 OCR 错误在控制面板显示，纯译文覆盖不插入错误提示。

保存设置会先停止当前会话，再应用新配置。普通翻译内容默认不写入日志；缓存仅在内存保留有限条目，重启后清空。

## 本地诊断

`GlassLingo.exe --self-test --with-paddle --soak` 会运行本地合成测试并写入 `diagnostics/report.json` 和界面截图，测试 API 使用本机模拟服务，不需要真实 API Key。此命令会短暂打开测试窗口。

合成测试包括：流式 UTF-8、断流拒绝、非流式回退、快速换字/取消、缓存、暂停、全屏 OCR 坐标、Paddle 子进程日语识别及停止释放、截图排除和 60 秒受控区域监测。它不代替实际游戏、真实网络和长时间真实场景验收。

0.6.0 曾用固定测试句验证当前 DeepSeek 服务的真实流式接口；0.6.1 的回归测试使用本机模拟服务，不发送用户截图、选区内容或 API Key。

0.13.1 起，小字重认按设置的物理像素行高阈值执行；设为 0 关闭放大重试，默认 24。提高阈值可能增加限频范围内的本地 OCR 工作。

## 0.14.0 区域与定位优化

几乎相同的选区（同一目标窗口、交并比至少 85%）会复用已有监测。部分交叠选区仍可独立存在，译文冲突时较早建立的区域优先显示；隐藏或移除该区域后，被避让的译文自动补回，无需重新翻译。避让保持各区独立的识别和翻译，不会合并不同区域的 API 请求。区域管理中可查看重叠提示。

普通浮窗与侧栏现在按目标屏幕的 DPI 和工作区放置。物理坐标边界已通过负坐标、副屏偏移与多种缩放尺寸的模拟验证；真实混合 DPI 多屏和游戏全屏模式仍建议实际复测。

日志单文件约 2 MB 后轮转，按 14 天、20 MB 总量策略维护，每分钟至多执行一次维护；检查间隔内可暂时超限。

0.14.1：输入与译文区的占位提示已调暗。普通浮窗/侧栏使用约 140 ms 柔和入场；覆盖字幕约 90 ms，第一帧就可读，不移动原文锚点、不等待动画后才出字。逐段流式不会反复淡入，系统关闭窗口动画时直接显示。

## 观影模式

主页“识别与翻译”下拉框选择“观影模式 · 快速响应”，然后用“区域持续翻译”框住视频字幕。正在监测时切换模式会保留选区；本地模型更换线程需重新加载，切换时可能有短暂间隔。设置 → 性能也可保存模式，按原有设置保存规则停止活动监测。

游戏模式保持低占用默认与自定义线程/检查间隔。观影模式使用更积极的本地处理：约 80ms 检查节奏、4 个 Paddle 推理线程、正常进程优先级、更短换字确认与流式显示。工作耗时长于检查周期时不会并行堆积 OCR 请求。CPU 使用量会上升，静止画面仍复用文本与翻译缓存。

观影单行覆盖根据原文行高和当前屏幕 DPI 设置字号，默认游戏字号上限不限制它；最大字号仍有 72 DIP 安全上限。较长译文优先向选区两侧展开、按原文中心对齐；一行放不下时自动换行，字号不随句长缩小。多行或双语源字幕仍采用逐行布局，不能保证不同语言文字宽度完全相同。

观影模式强制屏幕流式显示，约 32ms 追平已收到文本；实际延迟包含截图、OCR、文字确认与 API 首字等待。API OCR 仍限频 2.5 秒，不建议用它追赶快速更换的电影字幕；推荐本地 Paddle 或已安装相应语言的 Windows OCR。网络翻译模型运行在服务商机器上，软件无法让它满速运行。

0.15.1：游戏与观影覆盖都以原文中心对齐，长句向两侧展开，超过宽度后自然换行。已取消 UI 末尾省略号；若选区高度或相邻文字确实没有足够空间，仍会提示空间不足，请扩大选区或切换浮窗查看完整译文。


0.15.2：框选只决定 OCR 截图范围。译文和底色的显示窗口会按实际内容尺寸扩展到选区之外，无需为长译文额外把 OCR 选区框高；仍以原文为中心，达到显示器边缘时平移或换行。若文字多到整个屏幕或相邻字幕之间也无法容纳，请切换浮窗/侧栏查看。


0.15.3：对本地 OCR 把句尾短字拆成独立文字框的情况，在翻译前按相邻位置与基线合并，使尾部与正文一起翻译、一起居中，不独立漂在旁边。合并采用保守规则，间隔较大的标签和不同文字行保留独立。若实际画面仍出现尾字漂移，需要原文与译文同屏截图来确认具体框关系。


0.15.4：持续字幕以整行句子为显示单元。同一行的片段先合句翻译，缓存和流式更新也共用一个整句中心及连续底色。全屏桌面文本仍按独立行列处理；明确分开的行、远距离栏目或按钮保留独立。


## 0.16.0 持续字幕整段显示

每个持续翻译区域只输出一整段译文和一块底色，全部识别文字合成整段请求；不再按 OCR 小框分别摆放。框选请只包含你要翻译的字幕，多个独立位置可使用多个区域。源文字整体包围盒决定字幕中心，字体仍依据代表字高与游戏/观影模式。全屏翻译保留原有逐点布局。

开始新的持续区域框选时会关闭之前的一次性翻译层，避免旧结果和持续字幕混在一起；已存在的其它持续区域继续保留。


## 0.17.0 延迟与字幕稳定

两种模式都锁住持续字幕的小幅字号/中心变化；流式扩为多行时保持第一行基线。超过稳定阈值的真实位置/字号变化需 3 次独立 OCR 布局确认，区域缩放或 DPI 变化则立即重新适配。边界空间不足时仍需调整位置，不能保证任何长文本都不移动。

游戏保持原来的低占用采样频率；高置信度清晰字幕可减少重复识别。观影检查周期约 50ms（工作较慢时按实际完成速度执行），清晰 Paddle 新句可少一次确认，小字已清楚时不反复放大；低置信度、疑似单字噪声、短数字变化和空白仍保留确认。Windows OCR 无置信度，不使用该单次确认快速路径。

流式收到的片段会更频繁交给显示端，观影用约 64ms 的短窗口衔接；这只平滑已经收到的文本，不会缩短服务商计算首字的时间。
