# 0.17.0 实现与验证记录

- RecognizeTileAsync 对已通过过滤的高置信度文本跳过小字放大：游戏阈值 .95、观影 .85。Observe 信任路径分别要求所有行 .95/.90，且规范化文本至少 6 字符、变化跨度至少 max(4,35%)，近似单字噪声仍需确认。空白不走快速接受，原有空白确认和恢复保留。
- 观影轮询/最低 OCR 间隔降为 50ms，静态兜底从 500ms 改为 200ms，像素指纹变化比例阈值 .0015（游戏仍 .006）；串行 OCR 与翻译并发上限不变。视觉 API 仍限频 2500ms，不声称能够让网络模型零延迟。
- WholeCaption 用规范化整段文本稳定确认、比较布局内容及缓存键；OCR 的换行/拆框变化不再单独使同一句请求失效。整段映射不复用片段锚点，非整段模式按原规则处理。
- CaptionStability 用首个有效字号/锚点为基准，小幅抖动保持；超过 max(3 DIP,20%) 的字号变化或 max(8 DIP,.6×字号) 的位置变化，连续 3 个独立 OCR 对象确认才更新。相同源对象的流式帧不累加确认；区域大小/DPI 变化立即重置。旧的逐框字号单向缩小规则不再作用于整段字幕。
- 首行顶边以稳定锚点和单行行高计算，换行向下展开；在可用时限制宽度为锚点左右的对称空间，避免流式增长将整个字幕推向屏幕边缘。没有通过逐字改字号实现所谓平滑。
- FitDisplay 比较目标和实际 HWND 边界；相同时不重复 SetWindowPos/UpdateLayout。SSE 通知最短间隔 24ms（原 70ms），Movie StreamTextMotion 64ms 追平（原 32ms），让常见网络分块间隙有短衔接，同时无待显示文本时停止计时器。
- 新增受控检查覆盖高置信度/不确定/空白策略、字号和中心抖动、流式不计作 OCR 确认、真实持续改变可跟随、两种模式长流式换行的字号/中心/首行基线、模拟耗时 OCR 的重复工作与响应，以及同句分行不取消请求。现有真实 Paddle 与单块字幕回归继续执行。
- 相同内容也发布新的 OCR 布局证据，使三次几何确认能收敛；全屏逐点布局明确绕过整段稳定器，避免多个源框被锚到同一个中心。
- 最终受控小字换句结果：game 502ms / movie 216ms，分别在 1 / 2 次引擎调用内接受新句；使用 60ms 模拟识别及固定模拟翻译，不代表真实视频端到端延迟，也未测真实游戏 FPS。数据见 responsive-caption.json。
- 最终 0.17.0 发布构建 293 项断言通过、0 项失败，报告晚于程序集，无错误文件；另有 17 项非断言观测记录。包含真实 Paddle、两种模式的流式基线/中心/字号、整句重排不重发和全屏独立布局回归。诊断进程已退出。

## 0.15.3 历史记录
用户明确“尾字分离”是最后几个字单独漂到旁边，不是换行或裁掉半个字。本次针对不同的问题路径处理，未再修改窗口尺寸。

- 原来的 OcrLayout.Normalize 只去重/排序，将同一基线的长主体与短尾识别框留成两个 OcrLine。TranslationSession 会据此给两行分别请求定位翻译；行缓存与覆盖也将它们视为独立文本，可能产生漂在旁边的短译文。
- 新增 JoinShortTails，在本地 OCR 归一化后、翻译/缓存之前保守重组。主体至少 8 字符，尾框 1–8 字符，基线中心差不超过较小行高的 22%，高度比例不超过 1.3，横向间隔 -2px 至 max(3px, .55×行高)，同时限制尾框宽度。中文/日文相邻尾字直接连接，拉丁词之间保留空格。
- 已有句末标点、明显隔开的标签、不同行与 OK/CANCEL/BACK/YES/NO/ON/OFF 等常见独立操作不合并。矩形合并成并集，置信度取已知最小值。没有把该规则套到无坐标的视觉 API 转录。
- 新增用例包括中文主体+尾字、英文词界限、远距离/不同基线/独立按钮/句末分隔，以及游戏/观影从拆框 OCR → 单句翻译请求 → 单块文字和底色的完整路径。用例源为受控构造，尚未取得用户实际帧截图，因此不能据此确认所有实际分离原因都已覆盖。
